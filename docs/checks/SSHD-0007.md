# SSHD-0007 — Idle SSH sessions are disconnected

| Field | Value |
|---|---|
| **ID** | `SSHD-0007` |
| **Module** | SSHD |
| **Base severity** | MEDIUM |
| **Tags** | ssh, remote-access, session-management |
| **Facts required** | `sshd.config` |
| **Since catalog** | 6 |
| **Platforms** | Linux, all distributions |

## 1. What is tested

`ClientAliveInterval` > 0, `ClientAliveCountMax` > 0, and their product ≤ **900
seconds**.

This is one check over two keywords, and deliberately so. Neither means anything
alone: interval 300 with count 0 never disconnects, and count 3 with interval 0
never probes. A check that read either in isolation would report a host with no
idle timeout as configured.

## 2. Why it matters

An idle SSH session is a session nobody is watching — the laptop is closed, the
terminal is behind a browser window, the desk is empty — and it is still
authenticated, still authorised, and still able to run anything the user can run.
That is the exposure an idle timeout closes: not an attack on the protocol, but
the ordinary case of an unattended authenticated shell.

The effective timeout is `ClientAliveInterval × ClientAliveCountMax`. Each keyword
has a value that disables the mechanism outright, and **`ClientAliveCountMax 0`
is the trap**: the interval is set, so the configuration looks correct, and sshd
probes forever without ever terminating the connection.

## 3. Source of truth

| | |
|---|---|
| Source | `sshd_config` `ClientAliveInterval` and `ClientAliveCountMax` |
| Daemon default when unset | **interval `0`** (no probe at all), **count `3`** |
| Reference | `sshd_config(5)` |

## 4. Distribution variations

None. No mainstream distribution sets either keyword, so an unconfigured host of
any flavour has no idle timeout.

## 5. Verdict table

| Result | Condition | Severity | Detail must state |
|---|---|---|---|
| PASS | both > 0 and product ≤ 900 | — | the effective timeout in seconds and both operands |
| FAIL | interval ≤ 0 | MEDIUM | that sshd never probes |
| FAIL | count ≤ 0 | MEDIUM | that termination is disabled outright, and that this is the case that looks configured |
| FAIL | product > 900 | MEDIUM | the product and both operands |
| FAIL | acceptable globally, disabled inside a Match block | LOW | the Match criteria, quoted |
| UNKNOWN | either value is not a whole number | `unparseable_source` | which keyword |
| UNKNOWN | either absent and an `Include` did not resolve | `ambiguous_system_state` | that the timeout is the product of both keywords |
| NOT_APPLICABLE | no sshd configuration | — | — |

## 6. Where this check cannot know

- **`TMOUT`.** A shell-level idle timeout covers a different case: `TMOUT` ends an
  idle *shell*, this setting ends an idle *connection*. A session holding a port
  forward with no shell is only covered by this one. Neither substitutes for the
  other and this check reads only `sshd_config`
- **whether the session is genuinely idle.** The client-alive mechanism measures
  channel silence, so a session running a long silent job — a large `rsync`, a
  migration — looks identical to an abandoned one and will be killed
- **screen-lock policy on the client**, which is the other place this exposure is
  closed and is not visible from the server

## 7. Known false positives

Hosts whose normal workflow is long-running foreground jobs will see real work
killed. The answer is `tmux` or `screen` rather than a longer timeout, but a
batch host that nobody logs into interactively has a defensible case for
suppression.

## 8. Remediation

| | |
|---|---|
| Summary | Set `ClientAliveInterval 300` and `ClientAliveCountMax 3`, and check that neither is zero. |
| Effort | LOW |
| Steps | set both keywords; **confirm `ClientAliveCountMax` is not 0**; verify with `sshd -T` rather than by reading the file; consider `TMOUT` as a complement, not a substitute; reload |
| Commands | `sshd -T \| grep -i clientalive` |
| **Caution** | **Required.** Long-running foreground work is killed when the connection drops. Tell users to run such work under `tmux` before shortening the timeout, or the first casualty will be a job somebody has been running for six hours. |
