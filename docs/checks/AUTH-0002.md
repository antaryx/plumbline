# AUTH-0002 — Password quality parameters require length and character variety

| Field | Value |
|---|---|
| **ID** | `AUTH-0002` |
| **Module** | AUTH |
| **Base severity** | MEDIUM |
| **Tags** | auth, pam, password, credentials |
| **Facts required** | `auth.pam` |
| **Since catalog** | 10 |
| **Platforms** | Linux, PAM hosts only |

## 1. What is tested

The effective `minlen` is at least **14**, and at least one character-class
requirement is actually in force.

## 2. A module with default parameters enforces very little

`pwquality.conf` as shipped is a file of comments: every setting is commented
out, so the effective values come from libpwquality's compiled-in defaults. A
host can have the module correctly installed, correctly enforcing, and still
accept an eight-character password.

**Length is the parameter that matters.** It is the only one an offline
cracking attack really feels — each additional character multiplies the search
space, while character variety adds a few bits once. Variety is checked as a
secondary constraint because length alone permits a fourteen-character password
that is one dictionary word repeated.

## 3. Positive credits are a discount, not a requirement

This is the trap the check mostly exists for.

pwquality expresses variety two ways. `minclass` names how many of the four
character classes must appear. The four credit settings — `dcredit`, `ucredit`,
`lcredit`, `ocredit` — are **credits** by default:

| Value | Means |
|---|---|
| `dcredit = 1` | a digit counts **extra toward minlen** — requires nothing |
| `dcredit = -1` | **at least one** digit is required |
| `minclass = 4` | all four classes must appear |

`dcredit = 1` has demanded no digit while reading exactly like a rule that
does. A configuration setting all four credits positive requires nothing at
all, and this check reports that as a failure with the reason spelled out.

## 4. Where the effective value comes from

pam_pwquality reads `/etc/security/pwquality.conf` **first**, and arguments on
the PAM line **override** it. This check resolves both in that order.

A check consulting only one source would be right on whichever kind of host it
was written against and wrong on the other — silently, because both forms are
common and neither looks incomplete read alone.

## 5. Unset is UNKNOWN, not PASS and not FAIL

Where `minlen` is set in neither the file nor the module arguments, this check
reports **UNKNOWN**.

The effective value then comes from libpwquality's compiled-in default, which
is a property of the package build rather than of this host, is not readable
from the filesystem, and has changed between releases. Assuming the strict
value would be a false PASS; assuming the weak one would be a FAIL drawn from a
guess. The finding says so and notes that setting it explicitly removes the
ambiguity as well as the doubt — which is what the hardening benchmarks require
anyway.

Same reasoning as SSHD's algorithm-list checks (WP-18): a value compiled into
the software is not a value on the host.

## 6. The standards disagree, and the check says which one it took

| | |
|---|---|
| CIS, DISA STIG | minimum **14**, with character-class requirements |
| NIST SP 800-63B | minimum **8**, and argues **against** composition rules — they push users toward predictable substitutions |

They are not reconcilable. This check takes the stricter one, because the
failing direction differs: a host with a fourteen-character minimum satisfies
both, and one with eight satisfies only NIST. The conflict is stated in the
finding's detail rather than hidden behind the number, so an operator who has
deliberately adopted the NIST position can suppress with that reasoning.

## 7. Verdict table

| Result | Condition | Severity | Detail must state |
|---|---|---|---|
| PASS | effective `minlen` ≥ 14 and a real variety constraint | — | both values and **where each was read from** |
| FAIL | `minlen` < 14 | MEDIUM | the value, its source, and the NIST/CIS disagreement |
| FAIL | credits all positive and no `minclass` | MEDIUM | **that a positive credit is a discount rather than a requirement** |
| UNKNOWN | a parameter is set nowhere readable | `fact_unavailable` | that the default is a property of the package build |
| NOT_APPLICABLE | no quality module in the stack | — | that AUTH-0001 reports the absence |
| NOT_APPLICABLE | no `/etc/pam.d` | — | that another mechanism authenticates here |
| UNKNOWN | `/etc/pam.d` unreadable, or an include unresolvable | `insufficient_privileges` / `ambiguous_system_state` | which |

NOT_APPLICABLE when no quality module exists: AUTH-0001 reports that, and
failing twice for one missing thing buries the finding that matters.

## 8. Where this check cannot know

- **whether existing passwords meet the policy.** It applies at the next
  change, so a host can pass and still be full of eight-character passwords set
  last year
- **`dictcheck`, `maxrepeat`, `usercheck`.** Worth setting, not tested — each
  would fire on defensible configurations more often than on dangerous ones
- **`enforce_for_root`.** Quality rules do not apply to root setting another
  user's password unless this is set
- **`local_users_only`.** A host federating to a directory service may enforce
  quality centrally instead

## 9. Known false positives

A host that has deliberately adopted NIST SP 800-63B's position: eight
characters, no composition rules, no expiry. Suppress with the reasoning
recorded — the disagreement is real and the finding names it.

## 10. Remediation

| | |
|---|---|
| Summary | Set `minlen` and a variety requirement explicitly in `/etc/security/pwquality.conf`. |
| Effort | LOW |
| Steps | Set them in the **file**, not as module arguments — it survives a stack regeneration and is identical across hosts; `minlen = 14`; prefer `minclass = 4` to credits; if using credits make them **negative**; consider `dictcheck = 1` and `maxrepeat = 3`, because length alone permits one word repeated; verify with `passwd` and a thirteen-character candidate |
| Commands | `grep -Ev '^\s*(#|$)' /etc/security/pwquality.conf`, `pwscore <<< 'candidate'` |
| **Caution** | Raising the minimum does not affect existing passwords. Pair it with forced rotation only for accounts people actually use — forcing it on service accounts breaks whatever holds their credential. |
