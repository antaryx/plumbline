# SSHD-0011 — No deprecated or truncated MAC is offered

| Field | Value |
|---|---|
| **ID** | `SSHD-0011` |
| **Module** | SSHD |
| **Base severity** | HIGH |
| **Tags** | ssh, cryptography, remote-access |
| **Facts required** | `sshd.config` |
| **Since catalog** | 6 |
| **Platforms** | Linux, all distributions |

## 1. What is tested

`MACs` is set to an explicit list containing none of the algorithms below.

## 2. Why it matters

The MAC is what stops an attacker on the path from **modifying** a session rather
than merely reading it. Encryption without integrity is not a weaker guarantee,
it is a different one, and a session an attacker can modify is not protected by
having been encrypted.

| Family | Why |
|---|---|
| **MD5** (any form) | Collision-broken since 2004 |
| **SHA-1** (any form) | Collision-broken in practice since SHAttered (2017); RFC 9142 deprecates it for SSH |
| **Truncated tags** (`-96`) | 96-bit tag reduces forgery resistance for a saving of four bytes per packet |
| **`umac-64`** | A 64-bit tag is short enough to forge with feasible work |

`none` fails for the obvious reason.

**Not failed here:** the non-ETM forms. MACs ending `-etm@openssh.com` apply the
MAC to the ciphertext (encrypt-then-MAC), the construction with the sound
security proof, while the plain forms MAC the plaintext. Both appear in OpenSSH's
defaults and neither is broken, so preferring ETM is a remediation
recommendation rather than a verdict.

## 5. Verdict table

| Result | Condition | Severity | Detail must state |
|---|---|---|---|
| PASS | explicit list, no weak entry | — | how many were listed, and the list itself |
| FAIL | explicit list containing a weak entry | HIGH | each weak entry and why |
| FAIL | `+` or `^` form adding a weak entry | HIGH | that the verdict does not depend on the unknown base list |
| UNKNOWN | keyword absent, or a relative form adding nothing weak, or a `-` form | `ambiguous_system_state` | which case, and why it cannot be resolved |
| UNKNOWN | value unparseable as a list | `unparseable_source` | — |
| NOT_APPLICABLE | no sshd configuration | — | — |

## 6. Where this check cannot know

- **the built-in default list.** This is the whole reason an absent keyword is
  UNKNOWN rather than PASS. The effective list is compiled into the sshd binary;
  it changed between OpenSSH releases, and Red Hat's `crypto-policies` rewrites
  it at build and at runtime. Plumbline does not read the binary's version —
  that needs `sshd -T`, an `Exec` through the seam, deferred deliberately. Reporting PASS would assert the contents of a list never read
- **the relative forms.** `+`, `-` and `^` all modify the built-in list, so they
  inherit the same unknowability — with one asymmetry: a `+` or `^` that **adds**
  a broken algorithm is a definite FAIL, because that algorithm is enabled
  whatever the rest holds. A positive result survives incomplete knowledge; a
  negative one does not. Same asymmetry as ADR-0014, reached independently
- **what a client actually negotiates.** The list is what the server will agree
  to, not what any session used. `LogLevel VERBOSE` plus a packet capture answers
  that; configuration does not
- **`update-crypto-policies`.** On RHEL 8+ and Fedora the system policy can
  override `sshd_config`, so a correct file is not proof of a correct daemon
- **AEAD ciphers ignore this list entirely.** `chacha20-poly1305` and the `-gcm`
  modes carry their own integrity, so on a host whose `Ciphers` list is AEAD-only
  the `MACs` list governs only the fallback. It is still a negotiable path, so a
  broken entry is still a finding — but the practical exposure is narrower than
  the severity alone suggests

## 7. Known false positives

The same client-compatibility case as SSHD-0010. Older embedded clients
frequently offer only `hmac-sha1`.

## 8. Remediation

| | |
|---|---|
| Summary | Set an explicit `MACs` list of full-length SHA-2 and UMAC-128 constructions, preferring the ETM forms. |
| Effort | MEDIUM |
| Steps | set `MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com,umac-128-etm@openssh.com`; note that AEAD ciphers bypass this list; prefer the absolute form over `-hmac-sha1*`; check `update-crypto-policies --show` on RHEL; reload |
| Commands | `sshd -T \| grep -i '^macs'`, `ssh -Q mac` |
| **Caution** | **Required.** Older embedded clients offer only `hmac-sha1` and will disconnect with "no matching MAC found". Check management controllers and appliances before changing a host they reach. |
