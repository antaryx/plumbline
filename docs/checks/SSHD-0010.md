# SSHD-0010 — No deprecated or broken cipher is offered

| Field | Value |
|---|---|
| **ID** | `SSHD-0010` |
| **Module** | SSHD |
| **Base severity** | HIGH |
| **Tags** | ssh, cryptography, remote-access |
| **Facts required** | `sshd.config` |
| **Since catalog** | 6 |
| **Platforms** | Linux, all distributions |

## 1. What is tested

`Ciphers` is set to an explicit list containing none of the algorithms below.

## 2. Why it matters

The `Ciphers` list is what the server will agree to encrypt a session with. A
client chooses from it, so **the weakest entry is the weakest session this host
will ever carry** — and a client that prefers a weak cipher, whether through age
or through an attacker's influence over the negotiation, is not exotic.

Three families fail:

| Family | Why |
|---|---|
| **CBC modes** (`*-cbc`) | SSH's use of CBC lets an attacker who can inject ciphertext recover 32 bits of plaintext with probability 2⁻¹⁸ per attempt (CVE-2008-5161). Removed from OpenSSH's defaults in 7.6 |
| **64-bit block ciphers** (3DES, Blowfish, CAST-128) | Sweet32 (CVE-2016-2183) recovers plaintext from a long-lived connection carrying enough data — exactly the shape of a persistent SSH tunnel |
| **RC4** (`arcfour*`) | Biased keystream, prohibited for TLS by RFC 7465, removed from OpenSSH's defaults in 6.7 |

`none` fails for the obvious reason.

| | |
|---|---|

| Reference | `sshd_config(5)`, `ssh -Q cipher` |

## 4. Distribution variations

RHEL 8+ and Fedora govern this list through `crypto-policies`; the `DEFAULT`
profile excludes CBC, `LEGACY` re-enables it, and both override `sshd_config` in
some configurations. `update-crypto-policies --show` reports the active profile.
Debian and Ubuntu ship the upstream list unmodified.

## 5. Verdict table

| Result | Condition | Severity | Detail must state |
|---|---|---|---|
| PASS | explicit list, no weak entry | — | how many were listed, and the list itself |
| FAIL | explicit list containing a weak entry | HIGH | each weak entry **and why it is weak** |
| FAIL | `+` or `^` form adding a weak entry | HIGH | that the verdict does not depend on the unknown base list |
| UNKNOWN | keyword absent | `ambiguous_system_state` | that the list is compiled into the binary |
| UNKNOWN | `+` or `^` form adding nothing weak | `ambiguous_system_state` | that the remainder is the built-in default |
| UNKNOWN | `-` form | `ambiguous_system_state` | that removal cannot prove absence |
| UNKNOWN | value unparseable as a list | `unparseable_source` | — |
| NOT_APPLICABLE | no sshd configuration | — | — |

## 6. Where this check cannot know

- **the built-in default list.** This is the whole reason an absent keyword is
  UNKNOWN rather than PASS. The effective list is compiled into the sshd binary;
  it changed between OpenSSH releases, and Red Hat's `crypto-policies` rewrites
  it at build and at runtime. Plumbline does not read the binary's version —
  that needs `sshd -T`, an `Exec` through the seam, deferred deliberately. Reporting PASS would assert the contents of a list never read
- **the relative forms.** `+`, `-` and `^` all modify the built-in list, so they
  inherit the same unknowability — with one asymmetry: a `+` or `^` that **adds**
  a broken algorithm is a definite FAIL, because that algorithm is enabled
  whatever the rest holds. A positive result survives incomplete knowledge; a
  negative one does not. Same asymmetry as ADR-0014, reached independently
- **what a client actually negotiates.** The list is what the server will agree
  to, not what any session used. `LogLevel VERBOSE` plus a packet capture answers
  that; configuration does not
- **`update-crypto-policies`.** On RHEL 8+ and Fedora the system policy can
  override `sshd_config`, so a correct file is not proof of a correct daemon

## 7. Known false positives

A host that must serve genuinely old clients — embedded management controllers,
network appliances, legacy Java SSH libraries — may have no acceptable
intersection. That is a real constraint and a real risk, and it should be
suppressed with a justification naming the client, not resolved by pretending
CBC is safe.

## 8. Remediation

| | |
|---|---|
| Summary | Set an explicit `Ciphers` list containing only AEAD and CTR modes. |
| Effort | MEDIUM |
| Steps | find what actually connects first; set `Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes192-ctr,aes128-ctr`; **prefer the absolute form over `-*-cbc`**; on RHEL check `update-crypto-policies --show`; reload |
| Commands | `sshd -T \| grep -i '^ciphers'`, `ssh -Q cipher` |
| **Caution** | **Required.** Clients older than roughly 2014 may support nothing on a modern list and fail with "no matching cipher found". Inventory what connects before restricting, especially anything with out-of-band management. |
