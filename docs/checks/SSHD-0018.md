# SSHD-0018 — SSH agent forwarding is disabled

| Field | Value |
|---|---|
| **ID** | `SSHD-0018` |
| **Module** | SSHD |
| **Base severity** | LOW |
| **Tags** | ssh, remote-access, lateral-movement, credentials |
| **Facts required** | `sshd.config` |
| **Since catalog** | 6 |
| **Platforms** | Linux, all distributions |

## 1. What is tested

The effective global `AllowAgentForwarding` is `no`.

## 2. Why it matters

Agent forwarding places a socket on the server that anyone with root there — or
the user's own uid — can use to **sign authentication requests with the keys held
in the user's local agent**. The keys themselves do not move, which is what the
feature is usually defended with, but the ability to authenticate with them does,
for as long as the session is open. A compromised jump host can use a forwarded
agent to log into every other host that user's key opens, and the resulting
logins are indistinguishable from the real ones.

`ProxyJump` (`ssh -J`) achieves what agent forwarding is normally used for without
this property: the connection to the final host is negotiated from the client, the
intermediate host sees only encrypted traffic, and no socket is exposed on it. It
has been available since OpenSSH 7.3 (2016) and is the answer in almost every
case where agent forwarding is still configured.

This ships at LOW because the exposure requires the server to be compromised
first — but on a bastion, which is precisely where agent forwarding is most used,
that first condition is the whole threat model.

## 6. Where this check cannot know

- **that this is not a security boundary.** Anyone who can run a shell here can
  forward a connection themselves. The setting removes the default and the
  accident, not the capability
- **whether anyone actually forwards.** The server offers; the client decides
- **whether the keys in question are protected by a confirmation prompt**
  (`ssh-add -c`), which makes the exposure noisy rather than silent and is the
  mitigation on the client side

## 7. Known false positives

Deployment tooling that hops through this host to reach a git remote or a
downstream server relies on it. `ProxyJump` or a repository-scoped deploy key are
the replacements.

## 8. Remediation

| | |
|---|---|
| Summary | Set `AllowAgentForwarding no` and move users to `ProxyJump`. |
| Effort | LOW |
| Steps | establish the replacement first (`ssh -J`, or a `ProxyJump` line in `~/.ssh/config`); set the keyword; understand that this is not a boundary against a user with shell access; reload |
| Commands | `sshd -T \| grep -i allowagentforwarding` |
| **Caution** | **Required.** Pipelines that hop through this host will stop authenticating. Arrange `ProxyJump` or a scoped deploy key before the change rather than after the pipeline fails. |
